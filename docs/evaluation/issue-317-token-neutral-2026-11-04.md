# Issue #317 token-neutral evaluation

Date: 2026-11-04 (Asia/Shanghai)

## Decision

No new optimization is accepted by this evaluation. The constraint remains strict:
captain/member prompt, tool, schema, and call footprints must not increase in any
dimension. The exact before/after comparison required to prove neutrality is not
available, so the result is **not proven token-neutral**.

Command: `node scripts/tool-surface-budget.mjs` in the feature worktree, using
the current committed `lib/` generated by `pnpm build`.

| Surface | Tools | Schema bytes | Estimated tokens |
|---|---:|---:|---:|
| Captain | 19 | 20,356 | 5,089 |
| Core captain | 11 | 16,298 | 4,075 |
| Member | 4 | 5,551 | 1,388 |

The checked-in optimization summary records an older ledger of 20,003 bytes for
captain and 15,945 bytes for core captain. That is not an exact baseline for this
measurement: the build/runtime cohort and intervening changes were not
reconstructed as a paired run. The 353-byte differences therefore cannot be
attributed to #317 or treated as a measured before/after delta.

## Scope and next evidence

The existing `toolSurface: core` mode is already implemented; the current run
measures its surface but does not establish a newly proposed optimization. Do not
change the default surface or remove tools under #317 based on this evidence.
Any candidate must capture exact captain and member ledgers from the same
host/profile before and after, including prompt bytes, tool count, serialized
schema bytes, and call count. Reject it if any dimension increases.
