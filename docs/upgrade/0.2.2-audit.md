## 0. 结论速览

| 面 | 判定 | 影响 |
| --- | --- | --- |
| `dsh-agent` 模型选择 | **硬破坏（1 处）** | `installModelSelection` 从 2 参变 1 参；成员 fallback 路由在 0.2.2 上**静默失效**，不抛错 |
| `agent/request` 事件 | 语义降级（仍可用） | 被标 `@deprecated`；插件在 `src/harness-compat.ts:316` 用它做失败拒绝，0.2.2 仍生效 |
| `dsh-tools` | 重写但**兼容** | `ToolRuntime`→`ToolsService`（保留别名）；`defineTool`/`ToolRunContext`/`restrict` 形状不变；`presentAs` 扩展点被删（插件未用） |
| 工具调度 | **组合新增依赖** | 0.2.2 必须有 `ToolExecutor`；缺 executor 时所有 `agent_teams_*` 调用抛 `ToolExecutorUnavailableError` |
| `dsh-session` | **无变化** | `SESSION_FORMAT_VERSION` 两版都是 4；无存储迁移 |
| `dsh-llm` / `dsh-subagent` / `dsh-commands` | 纯增量 | 0 移除（`dsh-llm` 唯一影响是 `GenerateOptions` 泛型化，插件未传 `purpose`） |
| `cordis` 4.0.5→4.1.0 | 兼容但**有一处数值静默变更** | `LoggerLevel` 的 `INFO`/`WARN` 数值互换（插件只用方法调用，未用常量） |
| `schemastery` 3.18.5→3.19.0 | **无 API 变化** | 整包只有 `package.json` 不同 |
| 客户端包 | 纯增量 | 无符号移除；`SessionListState.projectionValues` 类型收窄（插件未用） |
| 清单 / engines | 无格式破坏 | `dsh-plugin.json` manifestVersion 0.15 契约未变；**宿主新增 `engines.node >= 24.9.0`** |

一句话：**代码层面只有 1 处必须改（模型选择 API），部署层面有 1 处必须补（工具 executor 的存在性）**，其余是"能跑但要知道"的语义变化。

## 2. 逐包变化

### 2.1 `@deepseek-ai/dsh-agent` —— 唯一的硬破坏（已验证）

| 项 | 0.2.1-rc.5 | 0.2.2-rc.1 |
| --- | --- | --- |
| `installModelSelection` | `(agentCtx: Context, selection: ModelSelectionRef) => () => void` | `(agentCtx: Context) => () => void` |
| `ModelSelectionRef` | `{ current: ModelSelection; assembled?: ModelSelection }`，导出 | **删除**（`lib/types/model-selection.d.ts` 整体消失） |
| 选择从哪来 | 调用方持有的可变 ref | 会话投影 `modelSelection`（`stateVersion: 3`，`{lastUsed, pending}` 均可为 `null`） |
| 谁写选择 | 插件直接改 `ref.current` | `agent.model.select(...)` → `session.append('model/selection', …)` |
| 新增导出 | — | `AgentModel`、`modelSelectionProjectionDefinition`、`ModelSelectionProjectionState` |
| `ModelSelection` | 在 `model-selection.ts` | 搬到 `lib/types/types.ts:69-76`，**仍导出**（`export * from './types.ts'`） |

**两个版本里 `installModelSelection` 干的事根本不同**（这是本审计最关键的一条）：

- 0.2.1（`dsh-agent/lib/index.js:166`）：挂 `system-prompt/assemble` 把 `selection.current` 注入 prompt 变量 `provider`/`model`，并记录 `selection.assembled`；再挂 `agent/request`，用 `selection.assembled` **重写** `LlmCallConfig` 的 `provider`/`model`/`reasoningEffort`。
- 0.2.2（`dsh-agent/lib/index.js:231`）：只挂 `agent/pre-step`，比较 `agent.session.requestHeader()?.config` 与本步的 `modelSelection`，不同则**追加一条模型切换提示消息**（`modelSwitchNotice`）。它**不再读调用方的 ref，也不再重写请求**。

`AgentModel`（投影 `key: "modelSelection"`，`stateVersion: 3`）：
`current()` → 先读投影 `pending ?? lastUsed`，没有就回落到 `AgentOptions.provider/model/reasoningEffort`；
`select(selection)` → 与已记录相同则 no-op，否则 `session.append('model/selection', …)`。

新增会话事件类型：`'model/selection': ModelSelection`（`dsh-agent/lib/types/types.d.ts:108`，`a` 版无此声明）。
`'agent/request'` 现在带 `@deprecated Retained for existing listeners; do not add new listeners. Use agent.model.select() before step preparation … and AgentOptions.maxTokens for the output cap`；`'agent/request-error'` 载荷**未变**（`agent, turn, step, provider, failure, retryPolicy, signal`）。

## 4. 需要改 / 无需改，以及依据

### 4.1 必须改（1 处）：成员模型路由

**现象（已验证）**：`installModelSelection(childCtx, selectionRef)` 在 0.2.2 上多传的第 2 个参数被忽略，**不抛错**（`dsh-agent/lib/index.js:231` 的函数签名只有一个形参）。于是：

- `applyRouteToSelection(selectionRef, route)`（`src/members.ts:565-575`）改的 `ref.current/assembled` 在 0.2.2 上**没有人读** → fallback 切换不生效；
- `agent/request-error` 里的 fallback 重试（`src/members.ts:1005-1014`）会把请求**再打到刚刚失败的主路由**；
- 同时丢失 0.2.1 由 `installModelSelection` 提供的两个副作用：`system-prompt/assemble` 的 `provider`/`model` 变量注入、`agent/request` 的配置重写。

**为什么"静默"**：TS 只在按 0.2.2 类型构建时报 `Expected 1 arguments, but got 2`；本仓库 `devDependencies` 仍钉 0.2.1-rc.5（`package.json`），所以**当前构建是通过的**，只有升 devDeps 才会暴露。运行时是纯 JS，多余实参直接丢弃。

**修复方向（建议，未实施）**：在 `src/harness-compat.ts` 增加一层"选择通道"抽象，按能力探测二选一：

```ts
// 0.2.2+：宿主自己持有选择，插件只能通过 Agent 上的 Model 接口写
const model = (agent as { model?: { select?: (s: unknown) => void } }).model
if (typeof model?.select === 'function') model.select({ provider, model, reasoningEffort })
// <=0.2.1：保留现状 ref 路径
else { selectionRef.current = next; selectionRef.assembled = next }
```

要点：
1. 探测对象是 **Agent 实例**（`agent.model`），不是 `installModelSelection` 的 arity——后者在 0.2.1 也是 2 参，用 `Function.length` 判也不稳（有默认值/解构时不可靠）。
2. `installModelSelection` 在 0.2.2 上仍然要装（**1 参**），它负责模型切换提示；两版都装，参数按能力探测决定是否传 ref。
3. `AgentModel.select()` 对"与已记录相同"的选择是 no-op（`sameModelSelection` 分支），因此可以无脑调用，不需要自己去重。
4. `select()` 写的是 `session.append('model/selection', …)`（**推断**：在 `agent/request-error` 监听器里、retry 之前调用是合法的，因为同一会话的 append 允许，且 retry 会重新组装 call config；未运行验证）。
5. 冷启动路径**不需要改**：`agentOptions: { provider, model, reasoningEffort }`（`src/members.ts:1264-1270`）在 0.2.2 仍是 `AgentModel.current()` 的回落来源。

### 4.2 必须补（部署面）：工具 executor

**依据（已验证）**：`dsh-tools/lib/index.js:624-634`，`selectExecutor()` 取不到 provider 就 `throw new ToolExecutorUnavailableError()`；0.2.2 的 `dsh-base/cordis.patch.yml:501-505` 才第一次出现 `tool-executor-native`（`tool-executor-ptc` 默认 `disabled: true`）。

**影响**：本插件注册的 **23 个** `agent_teams_*` 工具（`grep "name: 'agent_teams_"` 实测）都是"注册进 tools registry"的普通工具，派发必须经过 executor。所以：
- 走 `dsh base` 组合的 profile：**自动有**，无需改；
- 自建最小组合（含 `scripts/harness-runtime-scenarios.mjs` 里拼 profile 的测试、以及 `plugin-manager-install` 类用例）：**必须确认组合里有 executor**，否则工具一调就抛。

这是"0.2.2 起，'注册了工具' 不再等于 '工具能跑'"的组合契约变化，需要在 `docs/`/README 的安装前提里写清楚。

### 4.3 需要更新但不是代码修复：兼容矩阵

- `compatibility.json:3` 的 `recommendedHost` 仍写 `0.2.1-rc.5`；`supportedHosts` 里没有 `0.2.2-rc.1`。
- `scripts/compatibility.mjs` 用 `minimumHost()` 推导 `engines.dsh`（当前 `>=0.1.2-alpha.2`），**加入 0.2.2 不应抬高下界**（它只是测试矩阵），但 `recommendedHost`/`previewTag` 要跟着动。
- `package.json` 的 `devDependencies` 全钉 0.2.1-rc.5：要和 0.2.2 的类型一起编译，才能暴露 4.1 节的 TS 报错。

### 5.2 建议固化成脚本

把 C1–C7 做成一个"宿主能力探针"，跑在每次宿主升级前（输入 = 一个解包目录或已安装的 node_modules）：

1. 断言 `agent.model` 存在且 `select` 是函数 —— 这是"选择通道"唯一可靠的分叉点（不要断言 `installModelSelection` 的 arity）。
2. 断言 `SESSION_FORMAT_VERSION`、`restrictableNames`、`deliverSubagentPrompt`、`followup` 四个符号都在。
3. 断言 `dsh-base/cordis.patch.yml` 里有 `tool-executor-*`。
4. 断言 `dsh-plugin.json` 的 `$schema` 仍被本地校验器接受（`scripts/dsh-plugin-manifest.mjs`）。

任何一条失败 → 该版本进入"需要新审计"队列，而不是"照抄上一次结论"。

### 5.3 一个已经能看出的结构性趋势（推断）

0.2.2 把"调用方持有可变选择"整体换成了"会话投影 + `session.append` 事件"：`ModelSelectionRef` 删除、`agent/request` 弃用、`installModelSelectionProjection` / `SessionHistoryController` / `recordSubagentModelSelection` 全部退场，`model/selection` 成为新的持久事实。**方向是清楚的：插件不再能"从外部改写一次请求"，只能"记录一个选择"。** 后续 0.2.x 若继续这个方向，下一批会动的会是"请求级覆写"类的所有剩余接口（`agent/request` 的删除、`AgentOptions` 上的 route 字段改成纯回落语义）。**这是推断，不是已验证事实。**
