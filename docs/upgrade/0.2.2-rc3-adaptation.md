# 适配 DSH 0.2.2-rc.3（AgentTeams 0.1.33）

> 本文记录 `0.2.2-rc.2 → 0.2.2-rc.3` 的实际迁移。它是对
> [0.2.2-migration.md](./0.2.2-migration.md) 与 [0.2.2-release-notes.md](./0.2.2-release-notes.md)
> 的**追加**；那两份（含 §10 的 rc.2 适配记录）是历史报告，原文保留不改。

## 结论（Verdict）

**rc.2 → rc.3 是真正的「只换字面量」RC 递进：零源码改动。** 这与上一轮 rc.1 → rc.2 正好相反——那次静态审计判「无破坏」被真机证伪，四处运行时契约（F12/F13/F14/F15）全部漏检。这一轮的结论由三层独立证据同向支撑，而不是靠「看起来没变」：

1. **产物级逐字节对比**：`dsh-upgrade-audit` 的 npm 闭包 339 → 340 包，**零移除**，仅新增 `dsh-deepseek-chat-import`（实验性对话导入，插件不使用）。GitHub range `dsh-v0.2.2-rc.2...dsh-v0.2.2-rc.3` 只有 **6 个 commit、0 revert**。
2. **内容有实质变化的包只有 14 个，全部落在 Web Client / UI / session 侧。** `dsh-subagent`、`dsh-agent`、`dsh-tools`、`dsh-session`、`dsh-system-prompt`、`dsh-session-projection` 的 `.js` 与 `.d.ts` **逐字节相同** ⇒ rc.2 世代修的四处兼容层在 rc.3 上原样继续有效。插件 `src/` 直接 import 的四个 client 包（`dsh-client-connection`、`dsh-client-store`、`dsh-client-ui-primitives`、`dsh-client-ui-slots`）**全部不在变化集内**。
3. **真机 CLI 证据**：同一棵 `0.1.33` 产物在真实 `0.2.2-rc.3` 安装树（328 包精确 cohort）上跑九个场景加两个冷恢复，成员激活链全绿，且两个已知 fixture 分歧与 rc.2 / rc.1 逐字相同。

1. **pnpm 重写 `pnpm-workspace.yaml`**（与 rc.2 同一坑）：`install --lockfile-only` 把严格 JSON 改成单行 JSON5-ish（裸键 `minimumReleaseAgeExclude:` + 单引号），`scripts/compatibility.mjs:6` 的 `JSON.parse` 直接抛 `SyntaxError`。修法同上一轮——把 pnpm 输出规范化回严格 JSON 并保留 `autoInstallPeers`/`allowBuilds`/`minimumReleaseAgeExclude` 三段（删了会 `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`）。
2. **`package.json` 必须保持 ASCII escape 形态**：`scripts/compatibility.test.mjs:88-104` 的 `synchronizing from the 0.1.27 manifest keeps the checked-in ASCII escapes` 会用 `JSON.stringify(...).replace(/[\u0080-\uffff]/g, ...)` 重新生成并断言与签入文件**逐字节相同**。用普通 `JSON.stringify` 改版本号会把 5 个非 ASCII 字符还原成真实字符，闸门立刻红。重写时必须带同一段转义。

此外 `verify:skill` 因 macOS Finder 生成的 27 个 untracked `.DS_Store`（其中 8 个在 `skills/` 下）而红，清理后 `DSH skill mirrors are up to date: 11 skills, 128 files`。

## 2. 为什么这一轮不需要源码改动

### 2.1 与 rc.2 的对照：两种不同的「无破坏」

上一轮的教训是**导出符号 diff ≠ 运行时契约 diff**：`dsh-subagent` 顶层 export 只加了一个符号，零 REMOVED，但破坏发生在 `SubagentRuntime` 的实例方法、进程稳定 symbol（`Symbol.for('dsh.subagent.deliverPrompt')`）和 interface 字段布局（`SubagentActivationSpec` 从嵌套 `request` 改成拍平）上。

这一轮的证据强度不同：不只是 export 列表相同，而是**整包 `.js` 与 `.d.ts` 逐字节相同**。前者只能说明「没有增删导出」，后者能说明「没有改实现、没有改 interface 正文」。所以 rc.2 世代建立的四处兼容层在 rc.3 上不是「大概还能用」，而是**面对完全相同的契约**。

即便如此，仍按上一轮的纪律跑了两层验证：定向 TDD（21 条，含四个破坏点的哨兵用例）与真机 CLI 场景（成员 turn 真实执行），不用静态结论代替运行时证据。

## 4. 回滚

本分支的改动全部落在**声明面**（cohort / 版本 / 矩阵 / lockfile / workspace），没有源码改动。回退只需把 `package.json`、`dsh-plugin.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`compatibility.json` 与三份 README/维护文档恢复，然后 `pnpm install --frozen-lockfile` 并重建 `lib/` 与 `lib/git-artifact-stamp.json`（否则 `git-artifacts` 闸门红）。因为没有源码改动，回退不涉及运行时行为差异——rc.2 世代修的 F12/F13/F14/F15 在 rc.2 上同样有效。
